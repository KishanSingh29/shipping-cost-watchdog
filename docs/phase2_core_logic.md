# Phase 2 — Core Logic

## What is implemented
- Validates shipment schema and rejects invalid records explicitly (it never silently drops rows).
- Buckets shipment dates to Monday week starts.
- Aggregates each directed `(origin, destination, route_type)` route-week using `sum(freight_cost_inr) / sum(quantity_tonnes * distance_km)`.
- Computes prior-week cost and a trailing 8-observed-week average after shifting the series, so current/future values do not leak into history.
- Computes same-week/same-route-type peer average excluding the current route.
- Produces a configurable deterministic flag and an eight-column CSV. Phase 2 intentionally leaves every `matched_note_id` blank and labels each flag `Yes`; evidence verification is Phase 3.

## Flag rule and starting thresholds
A row is flagged only when all are true: previous-week cost exists; prior-history average exists; peer average exists; current cost exceeds previous week; current cost exceeds prior-history average by 10%; and either it exceeds peer average by 10% or its own-history z-score exceeds 2.0. These are transparent starting thresholds, not learned parameters. Tune only with a documented evaluation set; do not tune against a hidden grader.

## Assumptions
- A route is directed `(origin, destination, route_type)`.
- The route-week cost is ratio of sums, not average shipment-level ratios.
- History means prior observed route-weeks, capped at 8; with no prior week the baseline is null and the row cannot be flagged.
- The peer mean includes all other routes of the same `route_type` in the same week. A missing peer baseline prevents flagging.
- Output includes only flagged rows, consistent with the supplied examples being a watchlist. `flagged=Yes` means the numeric anomaly was flagged; Phase 3 may later use `No (justified)` for a flagged anomaly with a verified supporting note, matching the example contract.
- Output CSV is written using Python's CSV writer via pandas, which correctly quotes commas in reason text.
